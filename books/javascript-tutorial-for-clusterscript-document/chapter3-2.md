## スクリプトを更新するときの注意

このチュートリアルでは、onStartに処理を書いて動作を確認していますが、onStartの中身は**新しいスペースが始まったときに一度だけ実行されます**。
つまり、ワールドの更新やスペースの再入室では、onStartが実行されない状態が発生します。
そのため、スクリプトを書き換えてワールドを更新した際は、「新しいスペースを始める」をするか、デベロッパーメニューから「新しくテスト用スペースをはじめる」を選択して、新しいスペースを立てて確認してください。

デベロッパーメニューから「新しいスペースをはじめる」が比較的お手軽です。

## cluster Scriptで変数を定義してみよう

試しに、以下のようなコードを書いてみましょう。

```js
const text_const = "constで定義された変数"
let text_let = "letで定義された変数"

$.onStart(() => {
  $.log(text_const);
  $.log(text_let);
})
```

このスクリプトを、cluster上で動かしてみてください。
cluster上で動かすと、このように表示されます。

![](/images/chapter3-2/image1.png)

では、コードの解説をします。

## 変数の定義のしかた

変数を定義するときは、`const`と`let`を使って定義できます。
以下のような書き方をします。
```js
const text_const = "テキストをtext_const変数に格納している"
let text_let = "テキストをtext_let変数に格納している"

// constとlet以外にもvarを使った宣言もできますが、これは使わないほうがいいです。
var text_var = "varを使って定義もできる（非推奨）"
```

では、constとletの共通点、違いについて解説します。

## constとletの共通点

constとletは、どちらも**同じ名前の変数を2つ以上定義できない**という特徴があります。
なので、例えば以下のようなコードを書くとエラーになってしまいます。

```js
const text = "このコードはエラーになる"
const text = "このコードはエラーになる"

$.onStart(() => {
  $.log(text);
})
```

試しにこのコードをVisual Studio Codeで書いてみると、変数名に赤色の波線が表示されます。
Visual Studio Codeのようなコードエディタには、こうやって間違った文法でコードを書くと、間違いを指摘してくれる機能があります。

![](/images/chapter3-2/image5.png)

試しに、このコードをclusterにアップロードしてみると、clusterでもエラーになります。

![](/images/chapter3-2/image6.png)

### constとletの違い

constには、**再代入ができない**という特徴があります。
一方でletは、**再代入ができる**という特徴があります。

つまりどういうことか、実際にコードを書いてみましょう。
まず、letの挙動を確認します。

```js
let text = "再代入をする前"

$.onStart(() => {
  text = "再代入をした後"
  $.log(text);
})
```

こちらのスクリプトを書いて、実際にclusterで動かしてみましょう。
すると、変数を定義する際は`再代入をする前`という値を入れていましたが、それが`再代入をした後`に書き換わって出力されていることを確認できます。

![](/images/chapter3-2/image3.png)

では次に、constの挙動を確認してみましょう。

```js
const text = "再代入をする前"

$.onStart(() => {
  text = "再代入をした後"
  $.log(text);
})
```

こちらのスクリプトを書いて、実際にclusterで動かしてみましょう。
すると、今度はエラーが発生してしまいます。
これで、constは再代入ができないということが確認できました。

![](/images/chapter3-2/image4.png)


## constとletはどのように使い分けると良い？

変数を定義する際には、基本的にconstを使い、途中で値を書き換える必要がある場合にはletを使う書き方が良いと思います。
値の書き換えをしながらコードを書いていると、どの場所でどのように値を書き換えたのか把握しきれなくなってしまう恐れがあります。
（短いコードなら問題ないですが、処理が長くなればなるほど大変になってしまいます）
そのため、基本的にconstを使うのがおすすめです。

:::details さっきの例で出てきたvarって何？
非推奨な書き方なので詳しく解説しませんでしたが、気になる人向け。
varは、**再代入ができる**、**変数の再宣言ができる**という縛りのゆるい変数定義ができます。

ただ、なぜこれが非推奨かといいますと、
- うっかり同じ変数名を宣言してしまい、バグの原因になる
- varはconstやletと違い関数スコープのため、ブロックスコープ内で宣言した変数が別の箇所に影響する可能性がある（スコープの話は後の章で解説）
- 関数スコープで巻き上げが発生するため、バグったときにわけわからなくなる可能性がある

巻き上げって何？と思った方は以下の記事を読んでみてください。
https://qiita.com/ist-t-s/items/49ed558bd837452353b8
:::

## ところで、$.onStart(() => {})の外側にコードを書いてもいいの？

変数の定義はonStartの外に書いても大丈夫です。
今回のコードで実行したいのは、`$.log()`の処理なので、その記述がonStart内にあれば問題ありません。
（私はゲーム開発あまりやらないので詳しいことはわかりませんが）Unityやゲーム開発のお作法で、変数宣言はonStartやonUpdateの外で行うというお作法をよく見かけます。
onStartやonUpdateの中で宣言する必要がないというのと、コードの保守性を良くするためとか、パフォーマンスの問題なのかな？と個人的には理解をしています。
特に固定値の場合は、処理の途中で宣言してしまうと後で探すのが大変になってしまいますので、コードの冒頭で定義しておくと良いと思います。
